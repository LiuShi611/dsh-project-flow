## 三、使用说明全文（1011 字，点「全文」看）

```
dsh-project-flow 使用说明

一、它是干什么的

把一个大任务拆成五段跑：问意图、规划、实施、自检、验收。

第一段和最后一段在你自己的对话里，中间三段各开一个独立的子会话，跑完就丢。三段之间只传任务书，不传过程。所以主对话里只会多出一条结果，不是整条流水。

同一时间只有一段在动，所以「现在跑到第几段」就是真实进度。

二、怎么开

在输入框敲 /flow 加任务描述，比如：

/flow 给这个 Python 项目补一套 pytest 测试，覆盖登录和支付

不带描述也行，它会先问你。

它会先问你要什么，跟你确认一份能逐条核对的要求清单，再往下跑。跑完给你汇报：哪几条做到了，哪几条没做到，返工几次，哪里还有风险。

三、出问题怎么办

跑崩了、窗口关了、插件重载了 —— 敲 /flow-status 看状态。显示「上次中断于」，就敲 /flow-resume 项目名，它按磁盘上留下的东西从中断那段接着跑，已经过的段不重做。

怀疑工作区有问题 —— 敲 /flow-doctor，只报告不动手。确认要修再加 fix：/flow-doctor fix。

跑完发现做错了 —— 先 /flow-snapshots 项目名，看有哪些快照能退。然后回滚，默认是干跑，只告诉你会动哪些文件，一个字节都不改。看清楚再真回滚。有两种粒度：整棵恢复到那一轮动手之前，或者只还原那一轮动过的文件、你手改的其他东西不碰。真回滚前它会自动再存一张，回错了还能再回去。

四、换模型

/flow-models 看五段各用什么模型。

/flow-set 实施 hy4flash 这样改，改完立即生效，不用重启。清空表示恢复成继承当前模型。

第一段问意图和最后验收跑在你自己的对话里，模型只能用界面顶部切，/flow-set 改不了这两段。

五、几点要知道

自愈只管「没跑完」，管不了「跑完了但是做错了」。后者靠回滚和自检。

回滚需要本机有 git。没有的话流水照常跑，只是不能用回滚。

快照不覆盖 node_modules、.venv、dist 这些目录，回滚也不会动它们。

回滚不改流程状态，段位和返工次数不会倒退。要重跑就在回滚后 /flow-resume，或者重新开一个。

一次跑完一整条流水，中途不能插话。要叫停就直接中断会话，之后还能接着跑。

六、装

dsh plugin --profile 你的profile名 add https://github.com/LiuShi611/dsh-project-flow

需要 Node 20 以上，DSH 0.2.0 以上。

个人学习、研究、非营利项目免费使用。商业用途请先找我要书面授权。

作者：刘适
```
