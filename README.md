# dsh-project-flow

给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 用的五段工作流插件。作者：刘适。

把一个大任务拆成五段接力：问意图、规划、实施、自检、验收。

## 为什么这么拆

一条对话跑大任务，越往后上下文越重，要么撑爆，要么上游报错，要么质量往下掉。

所以我把中间三段挪了出去。规划、实施、自检各自开一个独立子会话，跑完即弃，它们读过的文件、试错的输出都不会回到主对话。三段之间只传任务书：规划写给实施一份，自检不合格时再写一份修正任务书打回实施。

这样主对话只多出一条工具结果，不是整条流水。

同一时刻只有一段在动，所以「现在在第几段」就是真实进度，不用猜。第 1 段和第 5 段必须留在主对话——子会话问不了你，也汇报不了给你。

因为进度全部落在磁盘上，纯文件、不进数据库，它还能多做两件事：跑崩了从中断那段接着跑；跑完了发现改废了，退回去。

## 功能

### 五段与打回

- 第 1 段问意图在主对话完成：一次问一个问题，问出真实意图，和你确认一份逐条可核对的要求清单。
- 第 2 段规划产出施工任务书，第 3 段实施只按任务书干，不自己扩大范围。
- 第 4 段自检默认怀疑，逐条对照，必要时读文件核对，不只信实施环节的自述。
- 第 5 段验收在主对话完成：对照你最初的要求逐条核，说清哪几条做到、哪几条没做到、额外做了什么、返工几次。
- 自检不合格必须给出可执行的修正任务书。只写「不合格」按规则停机，不盲目返工。
- 返工上限可配，默认 2 次。用完停机交给你定夺：放宽要求、改方案，还是放弃。

### 自愈

- 单段异常自动重试，默认额外 2 次，间隔按次数递增。三次都不过才判失败，并在结论里写清真错在哪段、试了几次。
- 每段有自己的截止时间，默认 15 分钟。卡住即取消该子会话，按失败处理，不会让整条流水挂死。
- 你按取消不重试。那是叫停，不是故障。
- 进程崩了、插件重载、窗口被杀之后：运行锁带进程号与每分钟心跳，下次对同一项目动手时先判活，持有者已死且心跳过期的锁直接挪开接手续跑。
- `project_resume` 按磁盘上的 `02-plan.md`、`03-build-*.md`、`03-correction-*.md` 重建上下文，从中断的那一段接着跑。规划已过不重跑规划，实施自述已有不重做实施。
- `state.json` 写坏也能修：先改名留证，再按 01–05 产物推断段位重建，并从 `01-intent.md` 把意图与要求清单抠回来——这两项续跑必需，别处补不出来。
- 每次尝试与每个自愈动作都写进 `run.log`，超过 512 KB 自动轮转。

### 回滚

- 每次实施前打一张快照，实施后再打一张；真回滚之前再打一张 `pre-rollback`，回错了还能再回去。
- 两种粒度：`full` 整棵恢复到目标快照，连快照里没有的新增文件一起清掉；`precise` 只还原那一轮实施报告过或快照比对出来的文件，你手改的其他内容一个不碰。
- 默认干跑，先列出哪个文件会新增、修改还是删除，一个字节都不动；`dryRun: false` 才真的改。
- 快照存在项目自己的裸仓库 `.project-flow/<项目>/snap.git`，用 `--work-tree` 指到你的工作区。不会在你工作区里 `git init`，不产生你没要求的提交，工作区本来不是 git 仓库也能用。
- 快照仓库自带排除规则，`.project-flow/`、`.git/`、`node_modules/`、`.venv/`、`dist/`、`build/` 这些不会进索引。额外目录用 `snapshotExcludes` 加。

### 模型分工

- 第 2、3、4 段可以各用不同模型。
- 指定的模型在 profile 里没被授权时不崩，退回当前模型继续跑，并在结论里写明哪一段回退了、为什么。
- 第 1 段和第 5 段跑在主对话，模型只能用界面顶部的选择器切，插件没有这个权限。配置里的 `intentModel` 只是期望值，用来提醒你手动切。
- 改模型不用重启：覆盖文件在每次执行前重读，profile 文件与共享文件分层合并，早先写在共享文件里的单项设置不会因为 profile 文件出现就整个失效。

### 产物

`.project-flow/<项目名>/` 下全是普通文件：

```
01-intent.md          确定的意图与要求
02-plan.md            方案与施工任务书
03-build-N.md         第 N 次实施自述
04-check-N.md         第 N 次自检结论
03-correction-N.md    修正任务书（有返工时才有）
05-report.md          交接给验收
state.json            段位、状态、返工次数、中断信息、每次实施的快照与改动文件
run.log               每次尝试、快照与自愈动作
run.lock              运行中的锁，正常结束后自动删除
snap.git/             项目自己的快照仓库
```

迁移项目目录就能搬走全部记录，含快照历史。

## 用法

### 工具

| 工具 | 作用 |
|---|---|
| `project_run` | 跑第 2 至 4 段，返回一份压缩结果 |
| `project_resume` | 接续被中断的项目，从中断那段接着跑 |
| `project_doctor` | 体检遗留锁、损坏状态、悬空阶段；默认只报告，`fix: true` 才动手 |
| `project_snapshots` | 列出全部快照与每次实施动了哪些文件 |
| `project_rollback` | 回滚到某个快照，`full` 或 `precise`，默认干跑 |
| `project_status` | 看某个项目现在在哪一段；不带项目名就列出全部 |
| `project_models` | 看五段各用什么模型、自愈与快照参数 |
| `project_set_model` | 改某段模型，改完立即生效 |

### 斜杠命令

| 命令 | 作用 |
|---|---|
| `/flow 你的任务` | 开工作模式，把当前任务按五段跑 |
| `/flow-status` | 看当前项目跑到第几段、返工几次、上次中断在哪 |
| `/flow-models` | 看五段各用什么模型、自愈与快照参数 |
| `/flow-resume 项目名` | 接续被中断的项目 |
| `/flow-doctor [fix]` | 体检工作区，加 `fix` 才动手修 |
| `/flow-snapshots 项目名` | 看这个项目有哪些快照可以回滚 |
| `/flow-set 阶段 模型名` | 改某段用的模型，不用重启 |

## 安装

```sh
dsh plugin --profile <你的 profile> add github:<你的 GitHub 名>/dsh-project-flow
```

需要 Node 20 及以上、DSH 0.2.0 及以上。

## 配置

在 `cordis.patch.yml` 里改，或者用 `/flow-set` 在运行时改。

| 键 | 默认 | 作用 |
|---|---|---|
| `provider` | `spawn` | 默认子会话后端 |
| `intentModel` | 空 | 第 1 段期望的模型，只用于提示你切换 |
| `planModel` / `buildModel` / `checkModel` | 空 | 第 2、3、4 段的模型 |
| `planProvider` / `buildProvider` / `checkProvider` | 空 | 各段的子会话后端，留空用上面的 `provider` |
| `maxRework` | `2` | 最多返工几次 |
| `maxConcurrentProjects` | `2` | 同时能跑几个项目 |
| `maxStageRetries` | `2` | 单段异常后额外重试几次 |
| `stageRetryDelayMs` | `3000` | 重试基础间隔，第 n 次等 n 倍 |
| `stageTimeoutMs` | `900000` | 单段截止时间，毫秒，0 表示不限 |
| `staleLockMs` | `1800000` | 锁心跳超过这个时长没更新就算崩溃遗留 |
| `snapshotEnabled` | `true` | 是否在每次实施前后打快照，关掉就没有回滚 |
| `snapshotExcludes` | 空 | 额外的排除规则，逗号或换行分隔，叠加在内置清单上 |

## 限制

- 回滚需要 git。没有 git 时流水照常跑，只是每次会在结论里写「快照不可用」，`project_rollback` 会明确告诉你做不了。
- 自愈只管「没跑完」，管不了「跑完了但做错了」。后者是回滚和自检的事。
- `precise` 回滚依赖实施段自述诚实。它漏报的文件不会被清；要彻底干净就用 `full`。
- 回滚不改流程状态。`state.json` 里的段位、返工次数不会因为回滚而倒退；要重跑就在回滚后跑 `project_resume` 或重新 `project_run`。
- 大目录会拖慢快照。每张快照是一次全量暂存，几万个小文件或几个 G 的权重文件应该用 `snapshotExcludes` 排掉。
- 第 1 段和第 5 段必须在主对话，子会话问不了你，也汇报不了给你。
